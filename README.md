## 分类依据

分类仅使用协议中的 `categories: string[]`。功能标签来自实际文件名和目录内容；无直接文件的目录可使用有访问数量和深度边界的后代内容作为证据。后代抽样不宣称整棵目录树已遍历。

`蓝奏云源`、`非蓝奏云源` 按实际链接类型与真实后代聚合，其余为普通可多选标签。缺少明确内容依据的项目保留待分类记录，不凭源名称补出功能标签。

原582条开放分类记录已有429条依据实际内容或状态补类，仍有153条待分类。真实安装包标为“软件”，压缩文件标为“压缩包”，音视频、图像、文档与源码按实际声明扩展名或裸 API 文件类型标类；图标图片 URL 不作为文件类型。没有解压压缩包、没有根据原源标题猜包内内容，也不把“软件”冒称为已确认具体功能。完整解析且未列出文件或子目录才标“空目录”；访问失败和含未知子目录不当作空目录。分类逐源证据与未知边界见 `verification/v188/max-curation/classification-final-audit.json`。

## 单软件与版本

单软件整理源固定为 `local:lanzoumax-single-software`。普通出处目录沿用 `origin-` ID；多版本软件入口沿用 `software-` ID 和首个原始源 ordinal，其真实版本文件为该入口下的 `kind: 1` 成员。多个版本放在同一个软件入口中，保留 `id` / `parent` 层级。

归并要求：完整的叶目录、同一实际软件族、可确认的软件文件类型，以及绑定本次目录采集时间的独立下一页终止证明。仅按完全相同的真实分享 URL 去重，保留其全部出处；按文件名中的版本与记录时间排序。相对时间只用于排序换算，交付的原始 `time` 文本保持不变。

## 可用性与待核实项目

完整解析表示本次能够取得该目录内容。原有合集文件分享保留自 Max 资产，未逐文件宣称重新验证下载可用。上游返回遮蔽文件 ID `-1` 的记录没有可确认分享地址，不生成 `/-1` 链接，也不据此做单软件归并。

单一 UA 的取消页面、密码错误、网络失败、HTTP 400/404 或未解决的分页返回均不能当作“双 UA 明确取消”。只有 Android 与桌面 UA 都取得明确取消结果的目录才从主源文档隔离；隔离数据和移除映射继续留存。未完整解析的源保留并附实际异常状态。

部分大目录已取得188页、9,400条文件记录后，下一页返回 `state=4`。新会话浅页正常、直接深页仍失败，现有证据不能确定其上游原因，也不能声称这些目录已经到末页。

主工程保存逐源分页结果、内容分类依据、后代访问边界、终页证明、归并映射、隔离映射、待核实记录及结构校验报告，位置为 `verification/v188/max-curation/`。

## 工程文件与发布文件

- `sources.json`：工程中的明文 UTF-8 v2 源文件，供导入导出和统一编码器读取。
- `lzpmarket.json`：schema 1 仓库元数据，声明仓库名、发布者、版本及发布源路径。
- `sources.lzp`：发布步骤由统一编码器生成的 LZP1 源封装。
- `README.md`：本说明。

标准发布 ZIP 的根目录包含 `lzpmarket.json`、`sources.lzp`、`README.md` 和实际使用的可选 `assets/`。工程明文、开发缓存及整理中间证据不放入该发布 ZIP。发布者头像和仓库图标是独立字段；本工程未提供的图片字段保持为空。

格式和分类遵循主工程唯一合同 `docs/lzpmarket-protocol.md`。原始 `size`、`time`、`description` 及出处说明保留，不由轻量解析设置清空。
